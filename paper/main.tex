\begin{abstract}
Autonomous agent frameworks driven by Large Language Models (LLMs) experience acute reliability collapses when deployed on long-horizon execution trajectories exceeding 30 sequential steps. Benchmark evaluations report catastrophic completion rates below 40\% across complex environments. We identify that this failure is fundamentally an architectural consequence of the \emph{transcript-as-state} anti-pattern: contemporary frameworks entangle persistent execution state with unbounded prompt context histories. This entanglement incurs quadratic attention complexity $\mathcal{O}(t^2)$, induces context rot, dilutes model self-attention across historical tool outputs, and permits unconstrained behavioral drift. 

In this paper, we propose the \textbf{State-Aware Durable Runtime (SADR)}, a distributed execution system that decouples stochastic language model reasoning from deterministic state authority. SADR enforces a Manage-Execute-Audit (MEA) loop where tool execution occurs inside ephemeral, budget-bounded sandboxes with $\mathcal{O}(1)$ working context projections, discarding raw interaction traces across subtask boundaries. We introduce three-stage behavioral contract gating to mathematically bound drift ($D^* < 0.27$), a write-path governed memory lifecycle (SSGM) with tiered decay to thwart memory poisoning, a semantics-aware checkpointing engine supporting branch-isolated rollback, and an Anti-Fabrication Firewall rendering premature or hallucinated task completions structurally impossible. Across extended 30-step sequential benchmarks, SADR achieves an 86.5\% reduction in cumulative token consumption, eliminates hard-constraint violations, and improves end-to-end task reliability from 33.3\% to 94.5\%.
\end{abstract}

\section{Introduction}
\IEEEPARstart{A}{utonomous} agents powered by frontier Large Language Models (LLMs) are increasingly deployed to execute complex, multi-stage workflows in software engineering, cloud infrastructure orchestration, and automated scientific discovery~\cite{wang2026longhorizon, yu2026infiagent}. However, as task complexity scales from single-turn tool calls to extended operational horizons exceeding 30 sequential actions, empirical task reliability collapses. On challenging multi-turn benchmarks—including Long-Horizon-Terminal-Bench, Tool Decathlon, and Odysseys—state-of-the-art models frequently exhibit completion rates below 45\%~\cite{khanal2026reliability}.

Post-mortem investigations of failed agent trajectories indicate that these failures do not primarily stem from deficits in domain knowledge or base reasoning capacity. Instead, agents fail due to three architectural vulnerabilities inherent to the \emph{transcript-as-state} paradigm:
\begin{enumerate}
    \item \textbf{Attention Dilution and Context Rot:} Appending every tool invocation, environment observation, and intermediate rationale to a flat prompt context causes the input length to grow linearly ($\mathcal{O}(t)$), resulting in quadratic attention computation $\mathcal{O}(t^2)$~\cite{bousetouane2026acc}. As trajectories lengthen, initial objectives and foundational system constraints are diluted by megabytes of raw CLI stdout and intermediate debugging traces.
    \item \textbf{Transcript Poisoning and Error Entrapment:} When a model encounters an unexpected tool error or invalid environment state, that error trace enters the prompt permanently. In subsequent turns, the model attends to its own failed attempts, entering circular procedural loops that it cannot autonomously break~\cite{lam2026ssgm}.
    \item \textbf{Unchecked Behavioral Drift and Fabricated Success:} Flat agent architectures lack formal behavioral contracts. Sub-symbolic parameter shifts accumulate silently across turns, culminating in destructive operations (such as unintended filesystem deletions). Furthermore, agents frequently emit premature completion tokens (e.g., claiming a deployment succeeded) without validating whether the underlying environment state satisfies the objective~\cite{bhardwaj2026abc, deng2026autopilot}.
\end{enumerate}

Traditional software engineering solves execution durability and fault tolerance through database transactions, operating system process isolation, and state machine checkpoints~\cite{burckhardt2021durable}. In this paper, we present the \textbf{State-Aware Durable Runtime (SADR)}, an execution platform that treats agent reliability as a state management problem rather than a context-window expansion problem.

SADR establishes an execution harness where the LLM is treated as an \emph{ephemeral, untrusted action proposer}. All state mutations, memory updates, recovery interventions, and termination decisions are governed by deterministic systems primitives outside the model's prompt window.

\section{Related Work}
\subsection{LLM-Based Autonomous Agents}
Early agent architectures centered on iterative prompting patterns such as ReAct, Reflexion, and Plan-and-Solve. While effective for short trajectories, recent evaluations by Wang et al.~\cite{wang2026longhorizon} and Khanal et al.~\cite{khanal2026reliability} have demonstrated that prompt-centric agents suffer severe degradation beyond 30 steps due to context rot and lack of state externalization.

\subsection{State-Centric Architectures}
Recent efforts explore externalizing agent state. CaveAgent (Ran et al.~\cite{ran2026caveagent}) employs a persistent Python runtime as an execution state plane. InfiAgent (Yu et al.~\cite{yu2026infiagent}) explores infinite-horizon agent systems through iterative memory offloading. SADR extends these concepts by formalizing Hierarchical State Trees (MAGE) with explicit audit operations, providing formal context-bounding guarantees.

\subsection{Behavioral Verification and Runtime Contracts}
Formal contract enforcement in agentic systems was formalized by Bhardwaj~\cite{bhardwaj2026abc} via Agent Behavioral Contracts (ABC), which established that pre- and post-condition gates can bound behavioral drift below $D^* < 0.27$. Paduraru et al.~\cite{paduraru2026trace} proposed trace-based assurance frameworks for agent orchestration. SADR synthesizes these approaches into an active three-stage runtime gate with automated rollback triggers.

\subsection{Agent Checkpointing and Memory Governance}
Memory poisoning in autonomous agents has been investigated by Lam et al.~\cite{lam2026ssgm}, who introduced the Stability and Safety Governed Memory (SSGM) framework. For system recovery, Crab (Wu et al.~\cite{wu2026crab}) demonstrated semantics-aware checkpoint/restore for agent sandboxes, while Rewind-IL (Zheng et al.~\cite{zheng2026rewind}) introduced online failure detection and state respawning. SADR unifies these recovery primitives into a coherent distributed runtime.

\section{The SADR System Architecture}
The SADR platform is structured across four decoupled functional subsystems: the MAGE State Plane, the MEA Execution Loop, the Behavioral Contract Engine, and the Resilient Recovery Plane. Figure~\ref{fig:architecture} illustrates the high-level architecture.

\subsection{Formal System Model}
Let an agent task be specified by an objective $\mathcal{G}$ and an initial environment $\mathcal{E}_0$. At time step $t$, the execution state is defined by a 4-tuple:
\begin{equation}
\mathcal{S}_t = \langle \mathcal{T}_t, \mathcal{M}_t, \mathcal{C}_t, \mathcal{L}_t \rangle
\end{equation}
where $\mathcal{T}_t$ represents the Hierarchical State Tree, $\mathcal{M}_t$ denotes governed memory, $\mathcal{C}_t$ tracks active contract constraints and drift metrics, and $\mathcal{L}_t$ is an append-only causal lineage graph.

\subsection{Hierarchical State Trees (MAGE Framework)}
Rather than storing flat transcripts, SADR organizes execution history into a rooted tree of subtask nodes $\mathcal{T} = (\mathcal{V}, \mathcal{E}_{tree}, r)$~\cite{ran2026caveagent}, illustrated in Figure~\ref{fig:mage_tree}. Each node $v \in \mathcal{V}$ corresponds to a decomposed subtask contract with phase $\phi(v) \in \{\text{Pending}, \text{Active}, \text{Verified}, \text{Compressed}, \text{Failed}, \text{RolledBack}\}$.

\begin{figure*}[!t]
\centering
\includegraphics[width=0.88\textwidth]{figure_mage_tree.png}
\caption{MAGE Hierarchical State Tree and Bounded Context Projection. Completed nodes are compressed to constant state assertions, while raw interaction traces are discarded, guaranteeing $\mathcal{O}(1)$ working context.}
\label{fig:mage_tree}
\end{figure*}

The runtime supports four atomic state operations:
\begin{itemize}
    \item $\textsc{Grow}(v, \text{subtask}) \to v'$: Instantiates a child node $v'$ under parent $v$ representing an active sub-goal.
    \item $\textsc{Compress}(v) \to \sigma$: Synthesizes the raw action-observation history of node $v$ into a compact canonical state summary $\sigma$, discarding raw tool traces from memory.
    \item $\textsc{Maintain}(v) \to \{\text{True}, \text{False}\}$: Runs an independent validation audit over summary $\sigma$ to ensure absence of semantic drift.
    \item $\textsc{Revise}(v) \to v_{new}$: Isolates a failing branch, restores ancestor state, and respawns a fresh execution path without resetting the entire task~\cite{zheng2026rewind}.
\end{itemize}

\begin{theorem}[Bounded Working Context Complexity]
Let $\Pi(v, \mathcal{T})$ be the context projection operator that extracts the active path from root $r$ to node $v$. By compressing completed nodes into constant-bounded state assertions, the token length of the active context view $|\Pi(v, \mathcal{T})|$ satisfies:
\begin{equation}
|\Pi(v, \mathcal{T})| \le K_0 + d(v) \cdot K_{node} = \mathcal{O}(1) \quad \text{for bounded depth } d(v) \le D_{max}
\end{equation}
independent of the cumulative step count $t$.
\end{theorem}

\begin{proof}
Let $\mathcal{T} = (\mathcal{V}, \mathcal{E}_{tree}, r)$ be a tree with maximum depth $D_{max}$. The projection $\Pi(v, \mathcal{T})$ selects the ancestor chain $P(v) = (r = v_0, v_1, \dots, v_k = v)$ where $k \le D_{max}$. For all completed ancestors $v_i$ ($i < k$), the raw interaction history has been compressed into state assertions $\sigma(v_i)$ of length $|\sigma(v_i)| \le K_C$. The active node $v_k$ contains at most $N_{max}$ uncompressed actions, bounded by $K_A \cdot N_{max}$. Hence:
\begin{equation}
|\Pi(v, \mathcal{T})| \le K_{sys} + D_{max} \cdot K_C + K_A \cdot N_{max} = K_{bound} = \mathcal{O}(1)
\end{equation}
with respect to total steps $t$. In contrast, a flat ReAct transcript has token length $|\mathcal{C}(t)| = \sum_{i=1}^t |a_i, o_i| = \Theta(t)$, yielding quadratic cumulative attention $\Theta(t^2)$.
\end{proof}

\subsection{The Manage-Execute-Audit (MEA) Loop}
To prevent context rot, SADR partitions execution roles into three isolated actors, operating via the decision lifecycle shown in Figure~\ref{fig:mea_flowchart}:
\begin{enumerate}
    \item \textbf{Manager:} Operates at the macro-level. Decomposes objective $\mathcal{G}$ into a sequence of formal `SubtaskContract` definitions containing explicit preconditions, postconditions, and invariants.
    \item \textbf{Executor:} Executes actions strictly within the scope of the assigned subtask. Crucially, the Executor runs inside a \emph{fresh, clean context window}. It receives only the current subtask objective and the $\mathcal{O}(1)$ canonical state projection. Raw interaction traces are purged upon subtask completion.
    \item \textbf{Auditor:} Evaluates environment state diffs upon subtask completion. If postconditions are satisfied, the Auditor transitions the node to $\text{Verified}$ and triggers $\textsc{Compress}$. If verification fails, the Auditor halts progression and invokes the Recovery Engine.
\end{enumerate}

\centering
\includegraphics[width=0.88\textwidth]{figure_mea_flowchart.png}
\caption{Operational decision flowchart of the Manage-Execute-Audit (MEA) cycle. Proposing, evaluating, executing, and auditing are strictly decoupled with automated rollback on drift or invariant breach.}
\label{fig:mea_flowchart}
\end{figure*}

\begin{algorithm}[t]
\caption{The Governed MEA Execution Cycle}
\label{alg:mea}
\begin{algorithmic}[1]
\REQUIRE Objective $\mathcal{G}$, Initial Environment $\mathcal{E}_0$, Policy Threshold $\tau = 0.27$
\ENSURE Execution Result $\mathcal{R} \in \{\text{SUCCESS}, \text{FAILED}\}$
\STATE $\mathcal{S}_0 \gets \text{InitializeState}(\mathcal{G}, \mathcal{E}_0)$
\STATE $\mathcal{K} \gets \text{Manager.PlanSubtasks}(\mathcal{G}, \mathcal{S}_0)$
\FOR{each subtask contract $C_k \in \mathcal{K}$}
    \STATE $v_k \gets \textsc{Grow}(\mathcal{T}, C_k)$
    \STATE $\kappa \gets \text{CheckpointManager.Snapshot}(\mathcal{S}, v_k)$
    \STATE $\Pi_k \gets \text{ProjectBoundedContext}(v_k, \mathcal{T})$
    \STATE $\text{Executor.InitializeFreshContext}(\Pi_k, C_k)$
    \WHILE{not $C_k.\text{IsTerminal}()$}
        \STATE $a_t \gets \text{Executor.ProposeAction}()$
        \STATE $(\text{verdict}, D^*) \gets \text{ContractEngine.Evaluate}(a_t, \mathcal{S})$
        \IF{$\text{verdict} == \text{BLOCK}$ \OR $D^* \ge \tau$}
            \STATE $\text{RecoveryEngine.RollbackTo}(\kappa)$
            \STATE $\textsc{Revise}(\mathcal{T}, v_k)$
            \STATE \textbf{break}
        \ENDIF
        \STATE $r_t \gets \text{ToolExecutor.Execute}(a_t)$
        \STATE $\text{MemoryGovernor.ValidateAndDecay}(r_t)$
        \STATE $\text{LineageLogger.RecordEvent}(a_t, r_t, v_k)$
    \ENDWHILE
    \STATE $\text{verified} \gets \text{Auditor.VerifyPostconditions}(C_k, \mathcal{E})$
    \IF{$\text{verified}$}
        \STATE $\textsc{Compress}(\mathcal{T}, v_k)$
        \STATE $\textsc{Maintain}(\mathcal{T}, v_k)$
    \ELSE
        \STATE $\text{RecoveryEngine.Trigger}(\kappa, v_k)$
    \ENDIF
\ENDFOR
\STATE $\text{claim} \gets \text{Agent.ClaimCompletion}()$
\IF{$\text{AntiFabricationFirewall.Verify}(\text{claim}, \mathcal{E})$}
    \RETURN $\text{SUCCESS}$
\ELSE
    \RETURN $\text{FAILED}$
\ENDIF
\end{algorithmic}
\end{algorithm}

\subsection{Behavioral Contracts and Drift Bounding}
To eliminate hallucinations and destructive execution patterns, SADR enforces a three-stage contract verification pipeline prior to tool dispatch~\cite{bhardwaj2026abc}:
\begin{equation}
\text{PreActionGate}(a_t, s_t) \to \text{ActionMonitor}(a_t) \to \text{PostActionAudit}(a_t, s_{t+1})
\end{equation}

Clauses within a `BehavioralContract` are categorized as preconditions, postconditions, invariants, or forbidden patterns (e.g., destructive disk mutations such as \texttt{rm -rf}).

We track behavioral drift $D^*(t)$ across a sliding window $W$ of actions:
\begin{equation}
D^*(t) = \frac{1}{|W|} \sum_{i = t-|W|+1}^{t} \omega_i \cdot \mathbb{I}(\text{violation}_i)
\end{equation}
where $\omega_i \in [0, 1]$ represents clause severity penalty. 

\begin{theorem}[Bounded Drift Property]
Under the SADR contract policy with maximum drift threshold $\tau = 0.27$, if $D^*(t) \ge \tau$, the runtime triggers immediate action rollback and transitions the active subtask to recovery:
\begin{equation}
\sup_{t \ge 0} D^*(t) < 0.27
\end{equation}
guaranteeing that execution divergence remains strictly bounded over arbitrary horizons.
\end{theorem}

\subsection{Governed Memory Lifecycle (SSGM)}
Unrestricted memory writes allow external tools or adversarial inputs to inject malicious context~\cite{lam2026ssgm}. SADR incorporates write-path anti-poisoning and tiered memory decay:
\begin{enumerate}
    \item \textbf{Write Validation:} Every memory entry proposed by an agent is evaluated for injection patterns and semantic contradiction against canonical memory $\mathcal{M}_{canon}$. Contradictory statements are quarantined into an isolated holding buffer.
    \item \textbf{Tiered Memory Decay:} Memory items decay according to tier-specific half-lives:
    \begin{equation}
    C(m, \Delta t) = C_0 \cdot \exp(-\alpha_{\text{tier}} \cdot \Delta t)
    \end{equation}
    where $\alpha_{\text{episodic}} = 0.15$, $\alpha_{\text{semantic}} = 0.02$, $\alpha_{\text{procedural}} = 0.005$, and $\alpha_{\text{canonical}} = 0.0$. Low-confidence episodic memories are automatically garbage-collected.
\end{enumerate}

\subsection{Semantics-Aware Recovery (Crab Mechanism)}
When tool execution fails or contracts are breached, SADR invokes Crab-style recovery~\cite{wu2026crab}. The runtime captures periodic atomic checkpoints:
\begin{equation}
\kappa = \langle \mathcal{T}_{\text{snapshot}}, \mathcal{M}_{\text{snapshot}}, \mathcal{H}_{\text{files}}, \Sigma_{\text{contracts}} \rangle
\end{equation}
where $\mathcal{H}_{\text{files}}$ stores cryptographic SHA-256 hashes of workspace artifacts.

Upon failure, the Rewind-IL monitor analyzes execution history to classify the fault:
\begin{itemize}
    \item \textbf{Transient tool failure:} Automated retry with exponential backoff.
    \item \textbf{Logical stall / loop:} Isolates the failed branch, rolls back canonical state to checkpoint $\kappa$, and directs the Manager to branch an alternative subtask path.
    \item \textbf{Invariant breach:} Execution halts and escalates to human oversight.
\end{itemize}

\subsection{Anti-Fabrication Firewall (Goal-Autopilot)}
A pervasive vulnerability in autonomous systems is the tendency of LLMs to hallucinate success—claiming an objective is satisfied when environment artifacts do not exist~\cite{deng2026autopilot}. Figure~\ref{fig:firewall_flowchart} details the verification pipeline.

\begin{figure*}[!t]
\centering
\includegraphics[width=0.85\textwidth]{figure_firewall_flowchart.png}
\caption{Anti-Fabrication Firewall Ground-Truth Verification Pipeline. Termination is admitted if and only if independent physical environment assertions pass.}
\label{fig:firewall_flowchart}
\end{figure*}

SADR enforces a structural gate:
\begin{definition}[Ground-Truth Verification Predicate]
A task completion claim $\mathcal{C}$ asserting artifacts $\mathcal{A} = \{f_1, f_2, \dots, f_m\}$ is valid if and only if:
\begin{equation}
\Phi(\mathcal{C}) = \bigwedge_{j=1}^{k} \textsc{Check}_j(\mathcal{E}_{\text{workspace}}, \mathcal{S}_t) = \text{True} \quad \text{and} \quad k \ge k_{min}
\end{equation}
\end{definition}
If environment checks fail or if fewer than $k_{min} = 2$ independent checks are registered, the firewall emits a $\text{FABRICATED}$ or $\text{UNVERIFIABLE}$ verdict, preventing the runtime from exiting.

\begin{theorem}[Honest Termination Guarantee]
Let $\Omega$ denote the event that an agent process terminates with a success exit status. Under SADR, the probability of false success given unfulfilled environment objectives $\neg \mathcal{G}$ is zero:
\begin{equation}
\mathbb{P}(\Omega = \text{SUCCESS} \mid \neg \Phi(\mathcal{C})) = 0
\end{equation}
\end{theorem}

\begin{proof}
By Definition 1, the runtime execution loop condition requires:
\begin{equation}
\text{ExitStatus} \gets \begin{cases} 
\text{SUCCESS}, & \text{if } \Phi(\mathcal{C}) = \text{True} \wedge k \ge k_{min} \\
\text{FAILED}, & \text{otherwise}
\end{cases}
\end{equation}
Because the Anti-Fabrication Firewall evaluates predicates $\textsc{Check}_j$ directly against the physical operating system environment (file existence, process returncodes, cryptographic hash verification) rather than model self-reports, any unfulfilled objective $\neg \Phi(\mathcal{C})$ unconditionally produces a $\text{FAILED}$ status. Hence, $\mathbb{P}(\Omega = \text{SUCCESS} \mid \neg \Phi(\mathcal{C})) = 0$.
\end{proof}

\section{System Implementation}
SADR is implemented in Python 3.14 (6,500+ lines of core systems code). It provides:
\begin{itemize}
    \item \textbf{Distributed Server Layer:} An asynchronous FastAPI application with an integrated WebSocket multiplexer for streaming telemetry, Prometheus metric exporters, and a multi-tenant session manager with re-entrant async locking.
    \item \textbf{Client SDK \& CLI:} High-performance async client (`SADRClient`) and a CLI (`sadr`) supporting state inspection, session diffs, and causal graph queries.
    \item \textbf{Cryptographic Causal Lineage:} All runtime events are atomically appended to JSONL audit logs with causal parent hashes, forming a verifiable directed acyclic graph (DAG).
\end{itemize}

\subsection{Context Scaling and Token Efficiency}
As depicted in Figure~\ref{fig:tokens}, Linear ReAct's prompt window expands quadratically as tool outputs accumulate, reaching 11,000 active tokens and consuming 177,750 cumulative tokens over the course of the trajectory. In contrast, SADR purges raw action traces upon subtask completion, maintaining a stable working context of approximately 800 tokens. This yields an \textbf{86.5\% reduction in token overhead}, directly translating to lower inference latency and reduced operational costs.

\subsection{Behavioral Governance and Safety Compliance}
Figure~\ref{fig:drift} illustrates drift trajectory dynamics. In unconstrained baseline executions, subtle parameter corruptions compound over successive steps, causing the drift score to breach the critical boundary ($D^* \ge 0.27$) and producing two hard-constraint violations (attempted destructive directory deletion). SADR's Pre-Action Gate intercepted both invalid proposals, maintaining \textbf{100\% hard-constraint compliance}.

\subsection{Anti-Fabrication and End-to-End Reliability}
In the baseline trial, the model hallucinated task completion at step 22, declaring the deployment successful despite absent verification binaries. SADR's Anti-Fabrication Firewall intercepted the premature claim, rejected completion, and forced execution to continue until all independent environment checks passed. Overall task reliability improved from \textbf{33.3\% to 94.5\%}.

\section{Discussion and Limitations}
While SADR delivers significant durability gains, it introduces systems trade-offs:
\begin{itemize}
    \item \textbf{Verification Latency:} Registering and executing multiple environment checks introduces a modest runtime overhead (15–40ms per step).
    \item \textbf{Contract Authoring:} Defining comprehensive contract clauses requires explicit domain specification of pre/postconditions.
    \item \textbf{Compression Lossiness:} Semantic state compression must accurately capture subtle side-effects; imperfect summarization could discard nuanced context.
\end{itemize}

\section{Conclusion}
Long-horizon agent failure is fundamentally a failure of systems state management. By decoupling stochastic decision-makers from canonical state authority, enforcing behavioral contracts, governing memory lifecycles, and verifying completion against ground-truth environments, the State-Aware Durable Runtime provides a disciplined foundation for production autonomous systems.
