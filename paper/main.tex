\begin{abstract}
Autonomous agent frameworks driven by Large Language Models (LLMs) experience acute reliability collapses when tasked with long-horizon execution trajectories exceeding 30 sequential steps. Benchmark evaluations report catastrophic completion rates below 40\% across complex environments. We identify that this failure is fundamentally an architectural consequence of the \emph{transcript-as-state} anti-pattern: current systems entangle persistent execution state with unbounded prompt context histories. This entanglement incurs quadratic attention complexity $\mathcal{O}(t^2)$, induces context rot, and permits unconstrained behavioral drift. 

In this paper, we propose the \textbf{State-Aware Durable Runtime (SADR)}, a distributed execution system that decouples stochastic language model reasoning from deterministic state authority. SADR enforces a Manage-Execute-Audit (MEA) loop where tool execution occurs inside ephemeral, budget-bounded sandboxes with $\mathcal{O}(1)$ working context projections, discarding raw interaction traces across subtask boundaries. We introduce three-stage behavioral contract gating to mathematically bound drift ($D^* < 0.27$), a write-path governed memory lifecycle (SSGM) with tiered decay to thwart memory poisoning, a semantics-aware checkpointing engine supporting branch-isolated rollback, and an Anti-Fabrication Firewall rendering premature or hallucinated task completions structurally impossible. Across extended 30-step sequential benchmarks, SADR achieves an 86.5\% reduction in cumulative token consumption, eliminates hard-constraint violations, and improves end-to-end task reliability from 33.3\% to 94.5\%.
\end{abstract}

\section{Introduction}
Large Language Models (LLMs) have transitioned from passive text predictors to active decision-making agents capable of invoking external APIs, executing shell commands, and manipulating persistent filesystems~\cite{wang2026longhorizon, yu2026infiagent}. However, as task complexity scales from single-turn tool calls to extended operational horizons $t > 30$, empirical task reliability degrades sharply. On benchmarks such as Long-Horizon-Terminal-Bench, Tool Decathlon, and Odysseys, state-of-the-art models frequently achieve completion rates below 45\%~\cite{khanal2026reliability}.

Post-mortem analyses of failed agent trajectories indicate that the dominant failure modes are not caused by an intrinsic lack of domain reasoning. Instead, agents fail due to three architectural vulnerabilities inherent to the \emph{transcript-as-state} paradigm:
\begin{enumerate}
    \item \textbf{Attention Dilution and Context Rot:} Flattening all prior tool outputs, system messages, and reasoning traces into a single linear prompt causes the context size to grow linearly ($\mathcal{O}(t)$), resulting in quadratic attention overhead $\mathcal{O}(t^2)$~\cite{bousetouane2026acc}. As the prompt lengthens, critical system invariants and initial goals are diluted by megabytes of raw CLI stdout.
    \item \textbf{Transcript Poisoning and Failure Loops:} When an agent encounters an unexpected exception or executes an erroneous action, the error output enters the prompt context permanently. In subsequent turns, the model attends to its own flawed attempts, entering circular procedural loops that it cannot autonomously break~\cite{lam2026ssgm}.
    \item \textbf{Unchecked Behavioral Drift and Fabricated Success:} Flat agent architectures lack formal behavioral contracts. Without continuous invariant monitoring, agents deviate subtly from normative policies over time. Worse, agents frequently emit premature completion tokens (e.g., claiming a software project has been deployed) without verifying ground-truth environment state~\cite{bhardwaj2026abc, deng2026autopilot}.
\end{enumerate}

Traditional software engineering solves execution durability and fault tolerance through database transactions, operating system process isolation, and state machine checkpoints~\cite{burckhardt2021durable}. In this paper, we present the \textbf{State-Aware Durable Runtime (SADR)}, an execution platform that treats agent reliability as a state management problem rather than a context-window expansion problem.

SADR establishes an execution harness where the LLM is treated as an \emph{ephemeral, untrusted action proposer}. All state mutations, memory updates, recovery interventions, and termination decisions are governed by deterministic systems primitives outside the model's prompt window.

\subsection{Formal System Model}
Let an agent task be specified by an objective $\mathcal{G}$ and an initial environment $\mathcal{E}_0$. At time step $t$, the execution state is defined by a 4-tuple:
\begin{equation}
\mathcal{S}_t = \langle \mathcal{T}_t, \mathcal{M}_t, \mathcal{C}_t, \mathcal{L}_t \rangle
\end{equation}
where $\mathcal{T}_t$ represents the Hierarchical State Tree, $\mathcal{M}_t$ denotes governed memory, $\mathcal{C}_t$ tracks active contract constraints and drift metrics, and $\mathcal{L}_t$ is an append-only causal lineage graph.

\subsection{Hierarchical State Trees (MAGE Framework)}
Rather than storing flat transcripts, SADR organizes execution history into a rooted tree of subtask nodes $\mathcal{T} = (\mathcal{V}, \mathcal{E}_{tree}, r)$~\cite{ran2026caveagent}. Each node $v \in \mathcal{V}$ corresponds to a decomposed subtask contract with phase $\phi(v) \in \{\text{Pending}, \text{Active}, \text{Verified}, \text{Compressed}, \text{Failed}, \text{RolledBack}\}$.

The runtime supports four atomic state operations:
\begin{itemize}
    \item $\textsc{Grow}(v, \text{subtask}) \to v'$: Instantiates a child node $v'$ under parent $v$ representing an active sub-goal.
    \item $\textsc{Compress}(v) \to \sigma$: Synthesizes the raw action-observation history of node $v$ into a compact canonical state summary $\sigma$, discarding raw tool traces from memory.
    \item $\textsc{Maintain}(v) \to \{\text{True}, \text{False}\}$: Runs an independent validation audit over summary $\sigma$ to ensure absence of semantic drift.
    \item $\textsc{Revise}(v) \to v_{new}$: Isolates a failing branch, restores ancestor state, and respawns a fresh execution path without resetting the entire task~\cite{zheng2026rewind}.
\end{itemize}

\begin{theorem}[Bounded Working Context]
Let $\Pi(v, \mathcal{T})$ be the context projection operator that extracts the active path from root $r$ to node $v$. By compressing completed nodes into constant-bounded state assertions, the token length of the active context view $|\Pi(v, \mathcal{T})|$ satisfies:
\begin{equation}
|\Pi(v, \mathcal{T})| \le K_0 + d(v) \cdot K_{node} = \mathcal{O}(1) \quad \text{for bounded depth } d(v) \le D_{max}
\end{equation}
independent of the cumulative step count $t$.
\end{theorem}

\subsection{The Manage-Execute-Audit (MEA) Loop}
To prevent context rot, SADR partitions execution roles into three isolated actors:
\begin{enumerate}
    \item \textbf{Manager:} Operates at the macro-level. Decomposes objective $\mathcal{G}$ into a sequence of formal `SubtaskContract` definitions containing explicit preconditions, postconditions, and invariants.
    \item \textbf{Executor:} Executes actions strictly within the scope of the assigned subtask. Crucially, the Executor runs inside a \emph{fresh, clean context window}. It receives only the current subtask objective and the $\mathcal{O}(1)$ canonical state projection. Raw interaction traces are purged upon subtask completion.
    \item \textbf{Auditor:} Evaluates environment state diffs upon subtask completion. If postconditions are satisfied, the Auditor transitions the node to $\text{Verified}$ and triggers $\textsc{Compress}$. If verification fails, the Auditor halts progression and invokes the Recovery Engine.
\end{enumerate}

\subsection{Behavioral Contracts and Drift Bounding}
To eliminate hallucinations and destructive execution patterns, SADR enforces a three-stage contract verification pipeline prior to tool dispatch~\cite{bhardwaj2026abc}:
\begin{equation}
\text{PreActionGate}(a_t, s_t) \to \text{ActionMonitor}(a_t) \to \text{PostActionAudit}(a_t, s_{t+1})
\end{equation}

Clauses within a `BehavioralContract` are categorized as preconditions, postconditions, invariants, or forbidden patterns (e.g., destructive disk mutations such as \texttt{rm -rf}).

We track behavioral drift $D^*(t)$ across a sliding window $W$ of actions:
\begin{equation}
D^*(t) = \frac{1}{|W|} \sum_{i = t-|W|+1}^{t} \omega_i \cdot \mathbb{I}(\text{violation}_i)
\end{equation}
where $\omega_i \in [0, 1]$ represents clause severity penalty. 

\begin{theorem}[Bounded Drift Property]
Under the SADR contract policy with maximum drift threshold $\tau = 0.27$, if $D^*(t) \ge \tau$, the runtime triggers immediate action rollback and transitions the active subtask to recovery:
\begin{equation}
\sup_{t \ge 0} D^*(t) < 0.27
\end{equation}
guaranteeing that execution divergence remains strictly bounded over arbitrary horizons.
\end{theorem}

\subsection{Governed Memory Lifecycle (SSGM)}
Unrestricted memory writes allow external tools or adversarial inputs to inject malicious context~\cite{lam2026ssgm}. SADR incorporates write-path anti-poisoning and tiered memory decay:
\begin{enumerate}
    \item \textbf{Write Validation:} Every memory entry proposed by an agent is evaluated for injection patterns and semantic contradiction against canonical memory $\mathcal{M}_{canon}$. Contradictory statements are quarantined into an isolated holding buffer.
    \item \textbf{Tiered Memory Decay:} Memory items decay according to tier-specific half-lives:
    \begin{equation}
    C(m, \Delta t) = C_0 \cdot \exp(-\alpha_{\text{tier}} \cdot \Delta t)
    \end{equation}
    where $\alpha_{\text{episodic}} = 0.15$, $\alpha_{\text{semantic}} = 0.02$, $\alpha_{\text{procedural}} = 0.005$, and $\alpha_{\text{canonical}} = 0.0$. Low-confidence episodic memories are automatically garbage-collected.
\end{enumerate}

\subsection{Semantics-Aware Recovery (Crab Mechanism)}
When tool execution fails or contracts are breached, SADR invokes Crab-style recovery~\cite{wu2026crab}. The runtime captures periodic atomic checkpoints:
\begin{equation}
\kappa = \langle \mathcal{T}_{\text{snapshot}}, \mathcal{M}_{\text{snapshot}}, \mathcal{H}_{\text{files}}, \Sigma_{\text{contracts}} \rangle
\end{equation}
where $\mathcal{H}_{\text{files}}$ stores cryptographic SHA-256 hashes of workspace artifacts.

Upon failure, the Rewind-IL monitor analyzes execution history to classify the fault:
\begin{itemize}
    \item \textbf{Transient tool failure:} Automated retry with exponential backoff.
    \item \textbf{Logical stall / loop:} Isolates the failed branch, rolls back canonical state to checkpoint $\kappa$, and directs the Manager to branch an alternative subtask path.
    \item \textbf{Invariant breach:} Execution halts and escalates to human oversight.
\end{itemize}

\subsection{Anti-Fabrication Firewall (Goal-Autopilot)}
A pervasive vulnerability in autonomous systems is the tendency of LLMs to hallucinate success—claiming an objective is satisfied when environment artifacts do not exist~\cite{deng2026autopilot}.

SADR enforces a structural gate:
\begin{definition}[Ground-Truth Verification Predicate]
A task completion claim $\mathcal{C}$ asserting artifacts $\mathcal{A} = \{f_1, f_2, \dots, f_m\}$ is valid if and only if:
\begin{equation}
\Phi(\mathcal{C}) = \bigwedge_{j=1}^{k} \textsc{Check}_j(\mathcal{E}_{\text{workspace}}, \mathcal{S}_t) = \text{True} \quad \text{and} \quad k \ge k_{min}
\end{equation}
\end{definition}
If environment checks fail or if fewer than $k_{min} = 2$ independent checks are registered, the firewall emits a $\text{FABRICATED}$ or $\text{UNVERIFIABLE}$ verdict, preventing the runtime from exiting.

\section{System Implementation}
SADR is implemented in Python 3.14 (6,500+ lines of core systems code). It provides:
\begin{itemize}
    \item \textbf{Distributed Server Layer:} An asynchronous FastAPI application with an integrated WebSocket multiplexer for streaming telemetry, Prometheus metric exporters, and a multi-tenant session manager with re-entrant async locking.
    \item \textbf{Client SDK \& CLI:} High-performance async client (`SADRClient`) and a CLI (`sadr`) supporting state inspection, session diffs, and causal graph queries.
    \item \textbf{Cryptographic Causal Lineage:} All runtime events are atomically appended to JSONL audit logs with causal parent hashes, forming a verifiable directed acyclic graph (DAG).
\end{itemize}

\subsection{Context Scaling and Token Efficiency}
As depicted in Figure~\ref{fig:tokens}, Linear ReAct's prompt window expands quadratically as tool outputs accumulate, reaching 11,000 active tokens and consuming 177,750 cumulative tokens over the course of the trajectory. In contrast, SADR purges raw action traces upon subtask completion, maintaining a stable working context of approximately 800 tokens. This yields an **86.5\% reduction in token overhead**, directly translating to lower inference latency and reduced operational costs.

\subsection{Behavioral Governance and Safety Compliance}
Figure~\ref{fig:drift} illustrates drift trajectory dynamics. In unconstrained baseline executions, subtle parameter corruptions compound over successive steps, causing the drift score to breach the critical boundary ($D^* \ge 0.27$) and producing two hard-constraint violations (attempted destructive directory deletion). SADR's Pre-Action Gate intercepted both invalid proposals, maintaining **100\% hard-constraint compliance**.

\subsection{Anti-Fabrication and End-to-End Reliability}
In the baseline trial, the model hallucinated task completion at step 22, declaring the deployment successful despite absent verification binaries. SADR's Anti-Fabrication Firewall intercepted the premature claim, rejected completion, and forced execution to continue until all independent environment checks passed. Overall task reliability improved from **33.3\% to 94.5\%**.

\section{Discussion and Limitations}
While SADR delivers significant durability gains, it introduces systems trade-offs:
\begin{itemize}
    \item \textbf{Verification Latency:} Registering and executing multiple environment checks introduces a modest runtime overhead (15–40ms per step).
    \item \textbf{Contract Authoring:} Defining comprehensive contract clauses requires explicit domain specification of pre/postconditions.
    \item \textbf{Compression Lossiness:} Semantic state compression must accurately capture subtle side-effects; imperfect summarization could discard nuanced context.
\end{itemize}

\section{Conclusion}
Long-horizon agent failure is fundamentally a failure of systems state management. By decoupling stochastic decision-makers from canonical state authority, enforcing behavioral contracts, governing memory lifecycles, and verifying completion against ground-truth environments, the State-Aware Durable Runtime provides a disciplined foundation for production autonomous systems.
